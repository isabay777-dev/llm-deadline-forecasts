# Second-family replication of LLM deadline forecasts

## Question and estimand

On the same Apple M5 deployment, how accurately do the original time-scaled direct predictor and discrete termination hazard forecast natural completion of a Qwen response under decode contention? The primary contrast is **direct minus hazard** in mean Brier error. At token 32, each method uses the observed prefix, the same source calibration and the first five completed historical requests of that episode. A positive outcome requires the model's own natural end token by both the clock deadline and absolute generation step 1,024. Native token-ready time at token 32 starts the clock. For an eligible execution, average the three squared errors before aggregating. Negative contrast values favor the direct predictor. The unit of uncertainty is the held-out episode. An eligible execution has emitted token 32 and remains active immediately after it.

The new model and hardware scope are Qwen/Qwen2.5-0.5B-Instruct-GGUF, Q4_K_M, revision `9217f5db79a29953eb74d5343926648285ec7e67`, GGUF SHA-256 `74a4da8c9fdbcd15bd1f6d01d621410d31c6fc00986f5eb687824e7b93d7a9db`, and the original instrumented two-slot llama.cpp Metal server on one M5. The comparison changes both model family and parameter count. All predictor parameters are fitted afresh on Qwen source data. This tests transfer of the method under the same measurement approach. The live queue policy and zero-shot transfer of the previous fitted parameters are outside this experiment.

## Sampling before outcomes

Use the pinned first UltraChat 200k train_sft shard, SHA-256 `afa8fa7426081b2a0e732fb50dbb5cd402a28ad5f0dbe66c0d996d63e7220727`. Jointly group rows 0–7,999 by shared prompt ID or connected word-set Jaccard similarity of at least 0.85 under the original normalization. Exclude every component touching the first 4,000 rows. Verify that all original CPU sampling-frame prompts, all original Metal assignments and both live-series assignments occur among those first 4,000 rows. Select the lexicographically smallest prompt ID in each remaining component. Order families by SHA-256 of the JSON encoding of the salt `ai2-qwen-family-replication-1` and family ID. Walk that order, retaining only prompts whose actual chat rendering on Qwen yields at most 1,024 prompt tokens in the 2,048-token slot. Tokenization is an outcome-blind design operation. Record all rejections and keep the first 408 eligible families. Each group and each test case belongs to exactly one partition. Technical prompts for smoke and background load are distinct from study assignments.

The first 32 families provide training and the next 12 calibration, two generation seeds (17 and 29) per family in the idle regime. Administrative training caps use the original independent hash rule with the new sampling salt and levels 128, 256, 512 and 1,024 with probabilities 0.2, 0.2, 0.2 and 0.4. Trace collection always allows up to 1,024 generated tokens. The fitting code alone sees the training masks. Source calibration is uncapped through the study horizon. The original grouped hyperparameter selection and calibration procedures apply. The deadlines are the original procedure's quartiles of eligible calibration durations to natural stop or the horizon. Record their exact native-time values before evaluating held-out cases. This permits the time grid in seconds to differ across model families.

Four development episodes follow. Remaining groups are earmarked for up to 24 confirmation episodes. Each episode has five preceding historical families (seed 17), followed by eight fresh evaluation families (two seeds each). Both methods score the same 16 assigned executions. Only the competing-load regime is collected in development and confirmation. The background slot repeatedly decodes under the original contention setup. Source fitting, observation of shared decode, Qwen terminal-ID validation, trace completeness, and native clock checks must succeed before inference. The model, calibration and code for forecast generation must be frozen before confirmation. Each forecast uses information available at the landmark. Archive issued forecasts before releasing confirmation scores. Preserve failures, retries and assigned families. Eligible forecasts that are unavailable under the frozen direct support rule must be counted and reported. Complete-cohort equivalence requires both forecasts for every eligible execution.

## Prospective sample size and decision

The practical equivalence interval is [−0.01,+0.01] Brier. Target an expected 95% half-width of 0.0075, conditional on the development estimate. Aggregate development losses by episode, retaining each numerator S_j (sum of eligible paired losses) and count n_j. Let D=ΣS_j/Σn_j and let the development standard deviation s be the sample standard deviation of (S_j−D·n_j)/mean(n_j) over the four independent episodes. Only s and coverage enter the sizing decision. If development coverage is incomplete or s is undefined, suspend confirmation and document the reason. Choose the first integer N from 12 through 24 satisfying t(.975,N−1)·s/√N ≤ 0.0075. If no N meets the target, fix N=24 and label the planned precision target unattained. Store the selected N, forecast precision curve, development-score hash, exact ordered episode-plan hashes and protocol hash before the first confirmation episode. No interim estimates of the direction or size of the confirmation contrast inform collection, stopping or replacement.

For the final N episodes, report the request-weighted contrast D and D ± t(.975,N−1)·sd((S_j−D·n_j)/mean(n_j))/√N. Declare practical equivalence only when the full interval lies within [−0.01,+0.01] on the eligible cohort. An entire interval above +0.01 indicates a practical advantage for hazard; an entire interval below −0.01 indicates one for direct. Otherwise report the interval as inconclusive for practical equivalence or advantage. Direction alone does not establish a practical effect. Report all assigned and active counts, forecast support, exact deadlines and runtime gates. Coverage and deadline-specific descriptions are secondary. This prospective replication has no new test of the live scheduler or of performance on independent machines.
